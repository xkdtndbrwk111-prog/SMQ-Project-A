# HOJA 게임 개발 전환 — 실행 체크리스트 (2026-11-22)

> **프로젝트 초점 전환:** 문제은행의 콘텐츠 제작·교사 승인 단계에서 **Google Apps Script용 HOJA 게임 시험판 개발**로 작업 중심을 옮긴다. 기존 문제은행 검수 체크리스트와 승인 정본은 수정·폐기하지 않는다.
>
> **상태:** 요구사항 정리 / 코드 패치 미시작 / 실제 GAS 시험판 미생성 / 운영 배포 미실시. `[x]`는 합의 또는 소스 확인을 뜻할 수 있으며 구현·실행 통과를 뜻하지 않는다.

## 0. 기준 소스 / 원칙
- [x] 게임 기준 저장소: `xkdtndbrwk111-prog/SMQ-Project-A`의 **7,208,766바이트** `Game.html` 분할본 (`versions/2.0.0/Game.html.parts/part-01~25.txt`) 및 루트 `Code.gs`, `UsageRollupU3S.gs`, `appsscript.json`.
- [x] GitHub 경로 `versions/2.0.0`는 **7MB 게임의 저장소 버전 표기**다. 실제 운영 GAS 배포 버전은 별도로 확인해야 한다. `versions/1.0.0`의 구형 마리오 백업과 혼동하거나 덮어쓰지 않는다.
- [x] 기존 서버의 카트리지 API: `hojaListPublicCartridges()` / `hojaGetPublicQuestions(names)` (최대 5개). 랭킹 API: `hojaRankList()` / `hojaRankSave()`. 이용 기록: `recordUsageStartU1()`.
- [x] **운영본은 보호**하고, 수동 편집이 가능한 별도 GAS 시험 프로젝트에서 작업한다. GitHub 커밋은 Apps Script 배포가 아니다.
- [ ] 운영 GAS 원본/배포 URL/설정·스프레드시트 연동 상태를 기록하고 시험용 프로젝트 복사본 생성.
- [ ] 원본 `Game.html` 복원 SHA-256과 시험판 기준 소스 확인, 변경 범위를 기록.
- [ ] 문제 공급·UI·게임 규칙 패치를 시험판에만 적용. 운영 URL/기존 학생 데이터 불변 확인.

## 1. Apps Script 내장 문제은행
- [x] **런타임에는 GitHub나 외부 Google Sheets에서 문제를 조회하지 않는다.** GitHub는 승인 원본·버전 관리·배포 준비용이고, 문항/보기/정답/해설/삽화는 Apps Script 안에 포함한다.
- [x] 최초 통합 대상은 사회 6학년 승인 정본 **2개 단원·64문항**. 정본 위치: `HOJA-QUESTION-BANK/approved/social/grade6/semester2/`의 각 ZIP **`effective/cartridge.json` + `effective/assets/`**. 이후 다른 승인 단원으로 확대.
- [x] 영어만 출판사·저자별 카트리지, 다른 교과는 출판사 구분 없이 관리. 기존 카트리지 다중 선택(최대 5개) 보존.
- [ ] 승인 ZIP 무결성 검증 후 GAS용 카탈로그·문항 코드 자동 생성(수동 복사·붙여넣기 가능한 단위로 분할).
- [ ] 현재 게임 RPC 응답 계약 준수: `questionSchemaVersion: 2`, `sourceSheetVersion: 1 또는 2`, `sheetName`, `familyId`, `type`, `options` 등. 기존 7MB 클라이언트 파서와 동작 대조.
- [ ] 게임 서버의 카트리지 목록/문항 조회 함수를 내장 로더로 연결. 운영 Sheets 문제 조회 의존성을 게임 경로에서 제거.
- [ ] 그림·분수·표·대화 등 미디어 및 의미 렌더링 보존. 기존 HOJA A/C/D 배치 및 교사 지정 C형 좌우 11문항을 독자 규격으로 바꾸지 않는다. 실제 7MB 게임 렌더러의 지원·누락을 먼저 실측한다.
- [ ] 기존 그룹 중복 방지, MCQ 원본 4보기 보존/실게임 3지선다, OX, 싱글 주관식 제외, 단원 혼합·무작위 출제 회귀.
- [ ] 카트리지 ID 전환 시 과거 랭킹·이용 통계의 식별자/교과 매핑 영향 확인. `SMQ_USAGE_SPREADSHEET_ID`·기존 `EVENT_LOG`·U3S 집계 데이터 보존.
- [ ] 사회 64문항 시험 성공 후 승인 정본 전체로 확대. 과학 64문항의 GitHub 정본 등록 여부는 독립 확인 후 포함한다.

## 2. 진입 화면과 QR 초대 — 두 싱글 모드 공통
- [x] 기존 **공용 카트리지 / 개인 카트리지** 구분은 신규 사용자 흐름에서 제거한다. 모든 사용자가 동일한 승인 문제은행에서 **학년→과목→1~5개 단원**을 선택.
- [x] 단원 선택 후 모드 선택: **싱글 아케이드 / 싱글 문제풀이 / 기존 팀전**. 팀전의 기존 규칙은 변경하지 않는다.
- [x] 두 싱글 모드 모두 **「학생 초대 QR 만들기」 / 「바로 시작하기」** 제공.
- [x] QR 화면에도 **「이 기기에서 시작하기」** 버튼을 둔다. QR 생성만으로 본인 게임 시작을 막지 않는다.
- [x] QR 링크에는 **모드 + 정렬·정규화된 카트리지 ID 목록**만 포함. 동일한 조합/모드는 교사와 상관없이 같은 링크; 별도 교사 계정·방·세션·만료·서버 저장 불필요.
- [x] QR로 입장한 학생은 과목·단원·모드·QR 메뉴를 생략하고 **선택된 모드의 게임 준비/진입 화면**으로 이동. 각 학생은 독립적으로 플레이. 일반 접속의 직접 선택 기능 유지.
- [ ] QR 주소 생성/파싱, 유효 카트리지·모드 검증(허용 목록), URL 길이/인코딩, 잘못된 링크 복귀 처리.
- [ ] 아케이드·문제풀이 각각 단일/복수 단원 QR→모바일 실기기 입장 시험.
- [ ] 같은 QR로 여러 학생 동시 접속, 개인별 진행 분리 및 QR 생성 기기의 직접 시작 확인.

- [ ] 단일 아케이드 정상 등록, 혼합 아케이드 등록 거부, 문제풀이 등록 거부 회귀.

## 4. 싱글 아케이드 게임 규칙 변경 요청
- [x] **게임 제한 시간: 현재 추정 600초 → 목표 900초.** 실제 소스의 현행 값을 확인하고 수정.
- [x] **각 스테이지 숨겨진 풍선: 5개 → 6개.** 추가 위치는 개발 측에서 레벨 충돌·이동 경로·난이도·접근 가능성을 확인해 선정.
- [x] **석양 전환 200초 / 밤 전환 100초** 규칙 유지. 기존 구현이 남은 시간 기준인지 확인해 동일한 의미로 적용.
- [x] **완료 조건은 25개 목표를 모두 찾았을 때 종료**로 유지(사용자 표현: “문제 25개를 다 찾았을 때”). 풍선 수가 늘어도 종료 목표를 30개로 변경하지 않는다. 실제 문제/풍선 카운터 결합 구조 확인 필요.
- [x] 위 항목 외 게임 물리·문제 정산·맵·난이도·랭킹 등 **나머지 규칙 변경 금지**.
- [ ] 기존 600초/풍선 배치/전환 조건/25개 완료 코드를 실제 게임 소스에서 추적.
- [ ] 각 스테이지 풍선 1개씩 위치 추가, 도달 가능성 및 기존 배치와 중복 여부 시험.
- [ ] 900초 타이머·남은 시간 200/100초 전환·25개 완료 시 즉시 종료·시간 종료 시 처리 회귀.
- [ ] 싱글 문제풀이에는 아케이드 타이머/풍선/스테이지 변경이 영향을 주지 않는지 확인.

## 5. 수동 작업 순서와 완료 판정
1. [ ] **우선:** 운영 GAS 프로젝트 복사→시험 프로젝트 이름/접속 URL 구분→원본 불변 확인.
2. [ ] 사회6 승인 정본 64문항 → 내장 `.gs` 소스 생성 → `Code.gs` 조회 함수 연결 → 카트리지 목록/단일/혼합 조회 검증.
3. [ ] 기존 게임 렌더러와 두 싱글 모드 시험(그림, A/C/D, 3지선다, 그룹, 주관식 배제).
4. [ ] QR 공통 진입 및 랭킹 분기 추가 → PC/Windows 전자칠판/모바일 시험.
5. [ ] 아케이드 900초·스테이지당 풍선6·200/100초 전환·25개 완료 조건 적용/시험.
6. [ ] 승인 문제은행 전체 확대, 데이터 무결성·성능·동시접속·랭킹/통계 격리 재검증.
7. [ ] 교사가 시험판 승인한 **이후에만** 운영본 교체 계획·백업·롤백 절차 확정 및 배포.

**매 작업마다 기록:** 수정 파일 경로/커밋, GAS 시험판 반영 여부, PASS/FAIL·시험 기기, 미해결 항목, 다음 1개 작업. **소스 수정 ≠ GAS 반영 ≠ 운영 배포**를 반드시 구분.
