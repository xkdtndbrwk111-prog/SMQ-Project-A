## 관찰 범위

- **PASS — 실험판 화면:** 원본 Maker가 브라우저에서 열리고 지도 목록, 파츠 팔레트, 캔버스, 속성 패널, JSON·실행취소 버튼이 표시됐다. 코드는 하나의 HTML에 CSS, 175개 PA1 PNG와 11개 HOJA 그림, 편집 로직이 합쳐진 구조다.
- **PASS — 격리 브라우저 자동시험:** `node --test verification/phase4e/reference-editor.test.mjs`. 원본 편집기의 샘플 JSON 저장, 확장 미지 필드를 포함한 파일의 불러오기→수정 없이 저장 후 필드 일치, 원본 편집기 Play Test→동반 V0.61 클라이언트 샘플 맵 로드, **별도** 현재 게임에 동일한 원본 JSON 직접 가져오기를 확인했다. 현재 시험 빌드에서 샘플 토관이 목적지 없이 생성되고 `pipeMode`를 `linked`로 바꾼 복사본은 목적지 맵 1로 생성되는 것도 확인했다. 실제 토관 이동이나 모든 지형·적의 플레이 동등성은 검증하지 않았다.
- **NOT RUN:** 실제 외부 Maker의 Play Test를 현재 HOJA 2.0 게임에 그대로 연결한 왕복, 학교 기기, 전체 편집 행위·모든 오브젝트·실제 교사 검수. 사용자 데이터는 사용하지 않았다.

## 실제 저장 형식과 현재 게임 비교

- 프로젝트 최상위 `format`, `schemaVersion`, `title`, `maps[]`; 맵 `id/name/theme/width/height/spawn/terrain[]/objects[]/events[]`; 좌표·크기는 16px 타일. 지형 객체는 `id/x/y/w/h/kind`, 배치 객체는 `id/type/x/y/w/h`와 종류별 속성을 저장한다. 예제의 토관·톱날·발판·대사와 실제 저장 JSON을 자동시험에서 확인했다. 조각/인스턴스/연결점 전용 필드는 확인되지 않았다.
- 기존 편집기의 객체 `type:saw`와 `patrol.waypoints/mode/speed`는 현재 게임의 `createMakerExtraObjects`/`makerHazards` 경로로 처리된다. Phase 4D의 `type:gimmick` + `gimmick.kind:saw/pendulum/fan/flame/stepping_blocks`는 공용 `model.js/runtime.js` 경로다. **두 톱날 경로가 공존**하며 모양·충돌·속도가 동등하다고 단정할 수 없다. 기존 `type:saw`를 자동으로 새 타입으로 바꾸지 않는다.
- 실험판의 `type:asset`은 `assetPath`, `frameCol/frameRow`, `collision`, `animationFps`, `opacity`를 저장한다. 현재 게임은 지정 atlas 타일의 solid/oneway/hazard와 특정 가시 hazard를 처리하지만, 임의의 모든 일반 에셋에 모든 충돌 설정을 부여하지 않는다. 편집기의 기능 선택과 실행 결과가 다를 수 있으므로 종류별 호환표·실제 플레이 검증이 필요하다.
- **샘플 토관 차이:** 편집기 `mkObj`는 `pipeMode:'solid'`를 기본값으로 만들고 `demo()`는 목표 맵·토관만 지정한다. 두 샘플 토관은 target은 있으나 `pipeMode:'solid'`다. 동반 옛 클라이언트는 target 유무로 연결을 판정하고, 현재 게임은 `pipeMode !== 'solid'`도 요구한다(`arcade.html` 4750행 부근). 실제 현재 게임 시험 빌드에서 원본 샘플은 목적지가 `null`, 모드만 `linked`로 바꾼 복사본은 맵 1을 가리켰다. 실제 S 키 왕복은 NOT RUN이다. 기존 파일을 자동 변환하지 않고 충돌을 알리는 비파괴 분석·교사 선택을 설계한다.
- 기존·현재 모두 이동 발판 변환에서 최상위 `speed`를 우선 사용하고 `patrol.speed`를 동일하게 옮긴다는 보장은 없다. 크기 변환도 동반 클라이언트는 `h=o.h*TILE`, 현재는 `h:8`이다. `patrol.mode/waypoints`, 몸체·시각·속도의 실기 비교는 별도 시험이 필요하다.
- 동일 6101 번호가 의미상 완전 호환을 보증하지 않는다. 새 기믹 필드를 기존 편집기에 로드해 **편집 없이** 다시 저장할 때 확장 필드는 보존됐다. 신규 기믹 선택·속성 편집 후 보존은 NOT RUN이다.
- `HOJA_V061_LOAD` 재전송 결함은 동반 옛 클라이언트와 현재 게임 모두에 같은 잠금 분기가 존재한다. 현재 게임을 대상으로 A→A→B 실패를 실제 재현했고 [재현 스크립트](../verification/phase4e/maker-import-repro.mjs)를 남겼다. 원본 편집기는 최대 16회 재전송하며 ACK를 받더라도 반복을 즉시 멈추지 않는다. 원본과 게임을 수정하지 않은 상태에서 외부 편집기→현재 게임 완전 연결이라고 주장하지 않는다.

## 권장 결론과 설계 반영

**실험판 편집기를 기초로 확장**하는 방안을 추천한다. 3열 UI, 지도 선택, 팔레트·검색·썸네일, 캔버스의 격자와 선택/이동, 타일 선택, 속성 패널, 자동 저장·JSON, undo, linked pipe UI 및 Play Test 흐름을 조사 후 재사용한다. 독립 실행 파일 한 덩어리를 그대로 정본화하기보다 변경 가능한 별도 소스와 원본 보존본으로 분리하고, 복제 전에 의존 리소스·라이선스 및 각 기능을 시험한다. 사용자의 감독 승인 전 UI나 게임을 변경하지 않는다.

1. 현 6101 데이터와 미지 필드를 보존하는 round-trip 및 샘플 토관·속도 차이 확인. 변경이 필요한 경우 원본 백업 후 경고·선택 기반 변환기.
2. 기존 수신 잠금 문제와 ACK/retry/오류·origin·버전 계약을 별도 승인된 최소 변경으로 해결하고 **실제 Maker → 현재 게임** 및 저장 전 시험→복귀→재시험을 검증한다.
3. 공용 model/runtime을 단일 게임 판정으로 쓰는 신규 기믹 속성 팔레트. 기존 legacy saw는 명시적 호환 계층으로 보존하고, 각 객체의 시각 에셋/충돌 동작을 구분한다.
4. 조각 라이브러리·배치·검증·미리보기를 기존 맵 문서에 비파괴 확장하거나 별도 문서로 표현하는 방안을 검토한다. 좌우 반전과 연결·ID·토관·물음표·난수 시드를 검증한다. 상세 제안은 [PHASE4E_DESIGN.md](PHASE4E_DESIGN.md).

감독 검토 전 구현 시작·운영 배포·main 병합은 하지 않는다.
