> **시험 복사본만 변경.** Project A/B 운영 Apps Script, 원본 `SMQ_USAGE_TELEMETRY`, `EVENT_LOG`, TOP25 랭킹, 운영 배포본·자동 트리거·삭제 함수는 변경하지 않았다.

- **같은 ID·같은 날짜·게임 내용 동일**이고 기록 시각만 변경된 재전송 2건은 고유 플레이에서 한 번만 계산. 서로 다른 게임 내용으로 같은 ID를 재사용하면 V4 집계 자체가 중단되도록 함. 기존 U2는 물리 행 수를 집계하기 때문에 누적 수치가 2회 더 높을 수 있음.
- SHA-256은 UTF-8 원본의 V4 정규화 고유 이벤트 내용과 정렬된 요약 버킷 각각에 대해 별도로 계산. 복사본에 먼저 `PREPARING` 집계행을 기록하고, **61일의 원본 구간과 버킷 3,969행을 모두 다시 읽어** 매니페스트의 SHA-256·건수·중복 수·원본 행 연속성 등을 대조한 뒤에만 `COMPLETE` 처리.
- 저장 중 API 호출 횟수 제한으로 일시 중단된 구간(2026-10-22)은 기존 저장 내용과 위치를 확인한 뒤 그대로 이어 기록했으며 **중복 집계행을 추가하지 않음**.
- `HOJA_V4_BACKFILL_AUDIT`는 백필 출처가 **실제 Apps Script 실행이 아닌 Google Sheets 연결 API로 실행한 독립 SHA 검증**임을 명확하게 표시함.
- 이 `COMPLETE`는 **격리 복사본의 데이터 셀 검증 상태**를 뜻하며, 운영 프로젝트 적용이나 원본 보관·삭제 가능 승인으로 해석하면 안 됨.

## 2. 실제 저장된 요약의 조회 시연

동일한 실복사본 `HOJA_V4_DAILY_MANIFEST` 및 `HOJA_V4_DAILY_BUCKETS`를 읽어 `HOJA_USAGE_V4_CORE.report()`를 직접 적용했다. 다음은 모두 **복사본에 저장된 데이터에서 검증한 값**임.

| 2026-11-23 (완료 61일 + 빈 오늘 꼬리) | 17,670 | 0 | 1,298 | 4,290 |

11월 23일은 **시험 복사본 시점에 오늘 원본 행이 0건**이었다는 뜻이다. 운영 실시간 원본에도 0건이라는 주장이 아니다.

- 학년별·교과별 합계는 17,670으로 플레이 총합과 동일.
- TEAM 총합과 팀 인원별 집계 합계가 일치하며 7팀도 분리됨.
- 기존 U2 `topCartridges`는 개별 단원이 아닌 결합 카트리지명 1개/플레이로 계산하며, `UNIT_SELECTION`은 별도로 총 18,659회.
- `HOJA_USAGE_V4_LIVE_TAIL.project()`는 인증된 과거 버킷을 읽은 후 오늘 원본의 **마지막 확정 원본 행 다음 부분만** 사용한다. 오늘 상태는 `LIVE_PROVISIONAL`; 오늘 데이터를 `COMPLETE`로 저장하거나 오래된 원본을 지우지 않는다.

## 4. 운영 전환 보류 조건

- **실 Google Apps Script 엔진에서 함수 실행은 아직 하지 않았다**. 시험용 Apps Script 프로젝트 설치/권한 부여 및 실제 OWNER/CREATOR 토큰 부여는 별도 단계다.
- 과거 기록이 날짜 정렬되어 있던 것은 **시트 복사 당시**의 성질이다. Project A의 실제 append 작업이 날짜 비역행과 늦게 들어온 전일 이벤트를 거부하거나 재빌드 요청하도록 수정되기 전까지, 실 운영 원본의 오늘 꼬리 조회 안정성을 최종 보장하지 않는다.
- Project A와 Project B의 서로 다른 GAS 프로젝트에는 **동일한 ScriptLock 공유가 자동으로 보장되지 않는다**. 실시간 조회의 일관된 절단점 구현 필요.
- 사용자 화면의 개별 단원명 정책, 새 완주/정답 이벤트(현행 EVENT_LOG에 없는 값), 독립 백업·복원·자동 30일/12개월 보관은 별도.
- **Project A/B 운영 배포, 데이터 실제 삭제, 자동 트리거 설치 모두 미실시**. 전체 현행 U2 비교, 실 GAS·권한·동시 append·중단/복구의 전수 시험 및 교사 승인 전까지 HOLD.
