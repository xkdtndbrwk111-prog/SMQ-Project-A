# HOJA QUIZ Phase 3B-2 — 격리 서버와 에뮬레이터 / 감독 검토 요청

기준 `87324afb9284b94c2bbc7d9c04a0ad778a952c8e`. 실제 학급 UI·게임 연결이나 운영 서비스를 구현하지 않았다. `verification/phase3b2/`의 서비스는 `demo-hoja-phase3a` 에뮬레이터 전용 Node 시제품이며 HTTP 엔드포인트·실제 배포 설정이 없다.

## 격리 및 실행 증거

임시 디렉터리에 Firebase CLI 13.35.1, Firebase JS 11.10.0, Admin 13.6.0, Rules 시험 도구 4.0.1과 Temurin JDK 21.0.13.1을 설치했다. Node 24.21.0 사용. CLI는 로그인 없이 demo 프로젝트와 Auth `127.0.0.1:19099`, Firestore `127.0.0.1:18080`를 기동하고 시험 후 정상 종료했다. 실제 프로젝트·서비스 계정·학생 정보를 사용하지 않았다. 도구/JDK는 임시 위치이므로 컴퓨터 재시작 후 남아 있다고 가정하지 않는다. `package-lock.json`과 `verification/phase3b2/README.md`에 재설치·재실행 방법을 기록했다.

서비스는 **SDK 초기화 전과 각 요청 전** 프로젝트 ID와 두 에뮬레이터 주소, 자격증명 환경변수 부재, 로컬 허브 및 두 서비스 응답을 검사한다. 실행기는 demo 프로젝트와 Auth/Firestore만 명시하고 별도 임시 CLI 설정을 사용한다. 실제 에뮬레이터를 끈 뒤 서비스 초기화가 실패한 것도 확인했다. 다만 이 검사는 시스템 전체의 범용 아웃바운드 방화벽이 아니다. 임의 코드의 모든 외부 접속 차단, 실제 배포 구성과 IAM은 후속 검증이 필요하다.

## Rules와 서버 신뢰 경계

기존 `verification/phase3a/emulator/firestore.rules`는 읽기/쓰기 모두 deny-all로 유지한다. 실제 에뮬레이터에서 인증 없는 읽기, 다른 학생 응답 읽기, 학생의 실행 점수·팀 집계 직접 쓰기와 교사 직접 읽기도 거부됨을 확인했다. 이 단계의 클라이언트 직접 읽기는 모두 막으며 필요한 정보는 시제품 서비스가 인증·권한을 검증한 뒤 반환한다. 아직 최종 클라이언트용 세분화 Rules는 없다.

Admin SDK는 Firestore Rules를 우회하므로 서비스에서 매 요청 Auth 에뮬레이터 토큰과 비활성화 상태, 교사 claim, 세션 소유자 또는 참가자 UID를 확인한다. 가짜 교사 claim은 테스트 준비 단계의 Admin SDK로만 부여했다. 학생의 방 생성·팀 배정·마감·재실행, 다른 교사의 방 제어와 다른 학생 참가 정보/영수증 접근을 거부한다. 학생 입장 요청의 임의 팀 지정은 거부하고, 소유 교사만 LOBBY에서 배정한다. 실제 교사 권한 발급·서명 토큰 검증·운영 IAM은 NOT RUN이다.

## 세션과 트랜잭션

- 교사 생성 `DRAFT`→공개 `LOBBY`→시작 `RUNNING`→마감 `CLOSING`→집계 `FINALIZED`, 사전 상태에서 `CANCELLED`를 구현했다. 시작 시 참가자와 팀을 동결하며 미배정 참가자가 있으면 시작을 거부한다. 세션 revision과 설정 revision을 증가시킨다.
- 방별 기본 900초·석양 200초·밤/안내 100초. 시작 전 교사만 변경 가능하며 300~1800초, 60초 단위, 비례 반올림은 승인 전 가안으로 `time-policy.mjs`에 격리했다. 시작 후 변경하지 않는다. 게임의 정지 가능한 시간과 서버 세션 벽시계를 합치지 않는다.
- UID별 신원 문서와 이름 문서를 트랜잭션으로 생성해 동시 중복 입장을 방지한다. 표시 이름이 같은 다른 UID는 자동 병합하지 않고 거부한다. 유효 기간이 있는 임의 입장 토큰은 해시만 저장하고 만료/위조를 거부한다. QR 공개·입장 승인·속도 제한·토큰 재발급 UI는 아직 없다.
- 서버 발급 run ID와 connection epoch를 관리한다. 재접속 후 이전 epoch의 신규 제출은 거부한다. 교사 승인 재실행 시 이전 run의 집계 기여를 무효화하고 새 run과 감사 기록을 만든다. 과거 영수증은 과거 수락 증거로만 보존한다.
- 동일 요청 ID·동일 결과는 수락 당시 영수증을 반환하며 마감 후·epoch 변경 후에도 인증과 소유권을 다시 확인한 뒤 조회할 수 있다. 같은 ID의 다른 본문은 충돌, 다른 ID의 같은 run은 이중 수락을 거부한다. 제출과 마감은 같은 세션 문서를 트랜잭션에서 읽어 직렬화한다. Firestore 충돌 재시도 한도를 넘거나 에뮬레이터가 경합 중 해당 트랜잭션을 닫았다고 응답하면 `RETRYABLE_CONFLICT`를 반환한다. 응답만으로 커밋 여부를 단정하지 말고 서버 상태·기존 영수증을 확인한 뒤 재시도해야 한다. 송신 시각을 근거로 마감 후 신규 결과를 소급 수락하지 않는다.
- 팀 집계는 같은 방에서 고정 인원 분모의 가안 평균 및 공동 순위만 계산한다. 전역/공식 랭킹과 다른 시간의 방 간 비교는 구현하지 않았다. QUIZ_25는 시간 보너스·랭킹 정책 미확정으로 `SCORING_POLICY_UNRESOLVED`를 반환해 수락하지 않는다. 현재 싱글의 잠정 점수·랭킹 정책을 바꾸지 않았다.

## 점수 신뢰 한계

서버는 세션·참가자·run 소유권, epoch, 게임/카트리지 버전, 필드와 범위, 정답·과일·기존 FINISH 시간 보너스 산식, 중복 수락을 확인한다. 하지만 게임을 서버가 재현하거나 관찰하지 않으므로 **자기 일관성이 있는 `otherPoints` 위조는 실제 시험에서 수락됐다.** 결과와 팀 집계는 `client_reported`로 표시한다. 이 시제품은 부정행위 방지나 공식 랭킹 자격 검증이 아니다. 허용 범위·신뢰 가능한 관찰 방식과 개인정보 보존은 별도 감독 결정이 필요하다.
