# HOJA 1.5 — 싱글 학생 참여 코드 · QR 직행 + 카트리지 표시명 통합 릴리스 지시서

**교사 확정 요구, 2026-11-24.** 이 문서는 구현 지시이며 기능이 이미 배포됐다는 뜻이 아니다. 동일 운영 GAS 프로젝트 / **기존 학생용 /exec URL 유지**. 별도 HOJA Game 2.0 개발과 혼동하지 않는다.

## 1. 교사 UX (두 싱글 모드 공통)
현재: 단원 1~5개 선택 → 혼자 놀기 → 아케이드 모드 또는 문제 풀이 모드 → 즉시 실행.
변경:
- 단원 선택 → 혼자 놀기 → **싱글 아케이드 / 싱글 문제풀이**
- 각 모드 선택 직후 **두 메뉴만 표시: [학생 참여 코드] [바로 시작하기]**.
- **바로 시작하기** = 교사 기기에서 기존 모드 그대로 실행, 불필요한 추가 단계 없음.
- **학생 참여 코드** = 화면 중앙의 아주 큰 5~6자리 코드 + 크게 스캔할 수 있는 QR + 참여 링크/복사, 뒤로, 만료/재발급, 교사가 같은 모드로 바로 시작하는 버튼. 85인치 전자칠판 뒤에서도 읽히도록 화면 대부분 사용. 글꼴 clamp(68px,9vw,144px) 등. 1920×1080/1280×720/390×844 반응형. 교사 추가 로그인·코드 입력을 요구하지 않음.
- 학생은 아이패드 카메라/크롬북 QR 스캔 후 브라우저에서 링크를 열면 **선생님이 선택한 승인된 문제 카트리지와 모드로 직접 들어간다**. 학년/과목/출판사/단원/모드 선택, 수동 코드 재입력, 대기실, 교사 시작 승인 요구 금지. 개별 학생이 스캔할 때마다 각 기기에서 독립적으로 게임 시작. 학생간 성적/진행 공유 없음.
- 화면/게임 실행 자체는 QR 접속으로 처리. iPad Safari의 자동 오디오 재생/전체화면 제한처럼 브라우저가 사용자 제스처를 요구하는 경우에 한해 **첫 화면 한 번 터치**로 소리 해제(게임 플레이를 위한 별도 선택 단계 불필요). 교사는 이를 문제로 보지 않으며, '모든 iPad에서 아무 터치 없이 소리까지 자동 시작' 보장 금지.
- QR 카메라를 쓸 수 없는 학생은 **학생 참여 코드 직접 입력** 화면을 통해 같은 세션으로 진입한다. 해당 입구를 실운영 기존 /exec에 추가, 구 '개인 카트리지 참여코드' 미완성 플로우와 혼동/재활성화 금지.

## 2. 세션·QR 백엔드 필수
- 동일 운영 GAS에서 **교사 선택 모드(arcade/quiz), 승인 카트리지 ID 1~5개, issued/expires, schemaVersion**만 담은 초대 세션을 발급하고 안전하게 조회한다. 세션 데이터는 공개 승인 콘텐츠에 대한 라우팅만 담당하며 문항 전문/개인정보/사용자 토큰은 담지 않음.
- 학생은 QR의 **기존 운영 /exec?join=<CODE>** 링크로 들어와, doGet(e)에서 전달된 코드로 서버에서 해당 세션을 조회한 뒤 기존 승인 `LIST`와 `GET`을 활용해 모드를 자동 실행. 임의 URL 파라미터로 비승인/비공개/구 개인 문제은행 우회 금지. URL에 있는 코드 자체는 공유 가능한 공개 수업 입장 키이므로 실제 사용자 계정 비밀번호와 별개.
- 다른 기기에 공유되어야 하므로 로컬스토리지/브라우저 CacheService만으로 만들지 않음. **PropertiesService 등 지속성 저장소에 TTL 기록** + CacheService 가속은 선택. 만료/삭제/재발급, 충돌 없는 난수, 동시 요청 락, 기본 과다 요청 보호, 서버 승인 목록 재검증. 코드 길이/문자 정책은 5~6자리 가독성 우선(혼동되는 0/O/1/I 배제)이며 수업 도중 쉽게 재발급 가능. 예시 만료 6시간은 세부 기본값이고 필요 시 수정 가능.
- 생성 엔드포인트가 익명 공개 웹 앱을 통해 호출되면 누구나 마음대로 생성해 GAS 할당량을 소모할 수 있으니 **교사 UI에서만 가능한 발급 권한/공격 표면을 점검하고 과다 요청 보호**. 학생 입장은 로그인 없이 가능해야 함. 기존 보드/앱 비밀번호를 QR에 노출하지 않기.
- QR은 프런트에서 같은 운영 웹앱의 링크를 인코딩. 별도 배포 URL, 학생 계정, Firebase/실시간 대전 서버 필요 없음.
- **모드 전환·QR 입장 시 상태 유지:** 교사 단원 1~5개, 실제 콘텐츠의 기존 canonical sheetName과 package pin, 현재 선택 모드 그대로 학생 단독 실행. 교사 바로 시작도 동일 선택 보존. 아케이드 랭킹은 기존 단일 승인 카트리지 조건과 학생 입력 규칙 유지; 복수 단원 및 싱글 문제풀이의 기존 랭킹 제한 유지. 원본 `GET`/RANK_SAVE/이용 통계/00:15 U3S 및 학생 기록 무변경.
- 현재 코드 위치: `experimental/unified-quiz-renderer/game-trial/part-11.txt`의 `HOJA_MODE_PREVIEW`, `stage==='solo'`에서 `window.HOJA_GAMEPLAY.launch('arcade'|'quiz',season)`로 직접 넘어가는 곳에 공통 하위 메뉴 삽입. **기존 연습모드, 팀전, 튜토리얼 동작 변경 금지.**

## 3. 승인된 23개 카트리지 이름도 한 번에 적용
- 40-6CB/CC의 기존 GitHub 패치 `experimental/usage-v4-unified/gas/ApprovedCartridgeDisplayClient.html` 및 `build_unified_gas.py`, `verify_release_candidate.py`, `verify_approved_display_client.mjs`를 통합.
- 카드에는 **단원 번호 위 / 짧은 승인 단원명 가운데 / PAK 01 등 제거**; 이미 들어온 교과·학년·출판사 정보를 반복하지 않음. ⓘ 전체 원본명 유지.
- **원본 cartridgeId·문항·정답·랭킹 저장 키·서버 LIST/GET 이름을 수정하지 않음.** 기존 게임의 단원 메타데이터를 직접 리네임하는 대신 23개 `pkg.id` 식별 기반 **표시 전용** 처리가 안전함.
- 40-6CA의 선행 질문창 준비와 다른 Claude가 진행하는 맵별 풍선 6개/총 30개, 25문항 성공 종료 코드가 있다면 최신 상태를 **덮어쓰지 말고** 함께 반영. 아직 검증 안 된 Phaser 35ms 제한 변경 금지.

## 4. 최소 합격 시험 / 배포
- 독립 기기/브라우저 간 **코드 발급 → QR 열기 → 지정 모드/지정 승인 카트리지 자동 진입**, 학생 코드 수동 입력 1회. 실기기 iPad Safari / Chromebook Chrome 확인 권장(처음 소리 터치만 허용).
- 바로 시작하기 2모드 정상, 수업 코드 오타·만료·재발급·다중 학생 독립 접속, 랭킹/GET 키 동일, 원본 학생용 URL 동일, 기존 23개 승인 카드 3개 대표 화면+PAK 숨김. **원래 23단원 전체 재검수·40인 부하 테스트·25풍선 전수 실행 금지**.
- 기존 운영 GAS HEAD에 안전하게 푸시·readback. 다른 개발 작업과 동시 HEAD 덮어쓰기 금지. 현재 카트리지 표시명은 GitHub에만 패치된 상태라는 교사 스크린샷 사실을 우선 고려.
- 학생용 `/exec`는 버전 고정: 코드를 올렸다고 라이브 화면이 바뀌지 않음. **교사에게 '배포→배포 관리→기존 학생 배포 수정→새 버전→배포' 요청**. `새 배포` 버튼 금지. 실제 변경된 새 버전 번호와 성공 스크린샷/테스트를 중앙 체크리스트에 기록 후 완료 보고.
- **이번 두 기능 모두 실제 운영에 반영되기 전에는 '완료', '출시'라고 하지 말 것.** GitHub 구현·로컬 검증·GAS HEAD 업로드·기존 배포 버전 갱신 4단계 상태를 구분할 것.
