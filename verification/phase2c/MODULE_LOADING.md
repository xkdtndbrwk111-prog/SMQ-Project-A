# 모듈 초기화와 실패 처리

아케이드는 동기 classic script로 동굴·지상 데이터, 부모 메시지, 오디오·물리·기믹, 몬스터 공통 시스템 및 9종, 입력·문항·HUD·기록·정산을 순서대로 등록한다. Scene과 RUN은 이후 게임 클로저에서 생성되고 필요한 참조가 팩터리에 전달된다. 오답 복습은 엔진 스크립트 뒤에 로드한다. 교사와 학생은 공용 서비스, 공용 게임 진입, 각 페이지 전용 스크립트 순서로 로드한다.

`tools/check_module_order.mjs`는 필수 스크립트의 개수, 동기 로드와 순서를 확인하며 빌드와 정적 검사에서 호출된다. 빌드는 추가로 로컬 JS 파일의 존재 여부를 확인한다. 테스트는 누락·비동기·순서 역전이 실패하는지 확인한다. 아케이드의 시작 전 확인은 Phaser, 월드·입력·시스템 팩터리 및 각 몬스터가 등록되지 않으면 이름을 화면에 표시한다. 부모 화면은 서비스, 게임 진입과 페이지 전용 등록이 없으면 오류를 화면에 표시한다. 브라우저에서 실제로 뗏목 모듈과 부모 서비스 로딩을 차단해 오류가 나타남을 확인했다.

이 검사는 지정된 모듈의 등록·연결을 점검하며 모든 외부 파일의 의미적 정확성이나 모든 실행 경로를 증명하지는 않는다.
