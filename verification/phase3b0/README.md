# Phase 3B-0 프로토콜 모의 시험

`node --test verification/phase3b0/model.test.mjs`

`model.mjs`는 Node 메모리에서만 동작하는 계약 예제다. 앱·엔진과 연결되지 않고 파일·네트워크·Firebase를 사용하지 않는다. 동시 요청은 실제 병렬 트랜잭션이 아니라 가능한 두 **직렬 순서**를 각각 실행한다. 사용자 역할은 단순 문자열로 흉내 내므로 인증·권한 체계의 보안 증거가 아니다. 서버/Rules/네트워크 차단을 구현하지 않았다.

| 지시 항목 | 모의 시험 |
| --- | --- |
| 동일 UID 중복 입장, 동명이인, 입장/동결 | 기존 참가자 재사용, 다른 UID 이름 충돌, 양쪽 직렬 순서 |
| 이전 연결 세대·중복 제출·마감 후 영수증 | 새 요청의 이전 epoch 거부, 동일 영수증 재생, 충돌 거부 |
| 마감과 신규 제출·늦은 오프라인 전송 | 제출 우선/마감 우선 두 순서의 포함 또는 거부 |
| 교사 권한·재실행·이전 기록 무효 | 단순 역할 모의, 재실행/제외 후 집계와 감사 확인 |
| 시간 위조·시작 후 변경·게임/카트리지 불일치 | 범위/정수/60초, 역할, frozen 설정 및 버전 거부 |
| 에뮬레이터 누락·실제 Firebase 우회·싱글 격리 | 함수 인자로 demo ID·loopback·두 서비스 가용성 및 허용 대상 검증을 흉내 냄. 실제 프로세스·네트워크를 확인하지 않음 |
| 900초 제품 규격·25번째 답변 | 모의 시계의 200/100초 및 일시정지, 25번째 종료. 현재 게임과 다르며 25번째 종료 정산은 미확정으로 거부 |

기존 `verification/phase3a/scenarios.json`의 24개 시나리오는 변경하지 않았다. 실제 인증·Firestore Rules·서버 SDK 권한·동시성·네트워크 격리, 실제 제품 시계 및 전체 플레이 네트워크는 후속 환경에서 별도로 시험한다. `demo-hoja-phase3a` 에뮬레이터의 CLI·Java 설치 방식과 현 상태는 `docs/HANDOFF_PHASE3B0.md` 참조.
