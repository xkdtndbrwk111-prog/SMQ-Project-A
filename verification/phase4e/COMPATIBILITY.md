# Phase 4E-1 Maker–게임 호환성 검증

기준: develop `42122df7f0ab727b339497ae534fb1d5785eaf4d`. 실험용 V0.61 원본 세 파일과 SHA-256은 수정하지 않는다. 원본이 최신 운영 정본이라는 뜻은 아니다.

## 원인과 수정

기존 수신기는 수신 잠금을 잡은 다음 같은 프로젝트면 잠금을 풀지 않고 반환했다. A → A → B에서는 B가 무시되었다. 실패 후에도 키를 성공처럼 기록했다. 수신 요청을 순서대로 처리하고 `finally`에서 잠금을 해제하며, 실제 성공만 저장한다. 같은 requestId의 재전송은 재시작 없이 ACK하고, 새 requestId로 같은 프로젝트를 다시 실행하면 처음부터 시작한다. 기존 requestId 없는 `HOJA_V061_LOAD/LOADED`도 받아들인다. 발신 창과 정확한 같은 origin만 허용하고, 선택적 gameVersion/dataVersion 불일치 및 잘못된 프로젝트는 오류를 반환한다. 응답은 해당 origin으로만 보낸다. 대기열은 최대 32개다.

원본의 사본인 `tools/maker_compat/maker.html`은 시험 빌드에만 포함된다. 기존 UI를 유지하며 현재 게임으로 전달하고 요청별 ACK, 실패, 15초 timeout, 창 닫힘과 재시작을 표시한다. 다른 요청의 늦은 ACK는 무시한다. 같은 게임 창을 재사용한다. 별도의 시험 호스트 `boot.js`는 내장 시험 카트리지와 기존 호스트 절차를 이용한다. 실제 게임 로직과 물리에는 시험 조작을 넣지 않는다. 정식 빌드에는 편집기 시험판·호스트·시험 프로브를 포함하지 않는다.

토관이 `solid`이면서 대상 링크가 있으면 경고한다. 저장 데이터는 바꾸지 않는다. 원본 샘플의 `pipe_a`는 위 방향, `pipe_b`는 왼쪽 방향이다. S키 왕복 시험은 **복사본에서 두 토관을 연결으로 명시하고 `pipe_b`만 위 방향으로 선택**했다. 원본은 변경하지 않았다. 기존 `type:saw`는 기존 Maker 톱날 경로, `type:gimmick`의 `kind:saw`는 신규 기믹 경로에서 각각 유지한다.

## 실행

저장소 루트에서:

```sh
node tools/build_current.mjs
HOJA_TEST_PROBE=1 node tools/build_current.mjs
python3 -m http.server 18210 --bind 127.0.0.1 --directory dist-current-test
```

브라우저에서 `http://127.0.0.1:18210/maker-compat.html`을 열고 팝업을 허용한다. **Play Test**를 누르고 게임 창에서 조작한다. 편집기로 돌아와 수정 후 다시 누르면 같은 창에 새 내용이 열린다. 토관 경고가 있는 원본 샘플은 빈 토관으로 유지되며 연결하려면 편집기에서 직접 연결을 선택해야 한다. 이 주소는 실행한 컴퓨터에서만 접근한다.
