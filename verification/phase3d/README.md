# HOJA 학급 개인전 및 대기실 검증

기준 `2610574432ae728b3debf65bac717a5a481efd30`. 이전 A/B 학급 팀전 요구는 사용자 정정으로 폐기되었다. 이 시험판의 학급 대전은 개인전이다. 다른 별도 게임을 변경하지 않았다.

## 재사용과 연결

- 마리오 2.0 `n3/web/board.html`, `classdata.js`의 1~5·6~10·11명 이후 배치, 공동 순위, 순위 이동, 낮은 순위부터 시상대 공개 및 문항별 정답률/보기 집계 개념을 HOJA 자료 형식에 맞게 구현했다. `intro.js`와 `index.html`의 중앙 대기실, `exam.js`의 입장·대기·결과 대기열 흐름도 참고했다. 원본 엔진·캐릭터·Firebase 통신 코드는 복사하지 않았다. `net/net.js`, `net/firebase.js`, `docs/HANDOFF_HOJA.md`, `docs/N6_FILES.md`, `REPORTS/INTRO_CLASS_2026-11-19.md`와 커밋 `d14d3f5`도 비교했다.
- 기존 HOJA 카트리지 선택 UI와 `HOJA_B_LIVE`가 선택한 1~5개를 그대로 전달한다. 단일·다중 선택 결과를 순서 있는 카트리지 ID와 버전으로 잠그고 QR 입장 시 검증한다. 학생은 교사가 고른 카트리지와 시간을 바꿀 수 없다.
- 기존 Phaser 아케이드와 문항별 응답 기록, 개인 복습, 점수 계산, 900초 설정 및 격리 Auth/Firestore 서비스와 중복 제출 방지를 재사용한다. 학급 결과는 싱글 랭킹으로 보내지 않는다. 시험판의 기존 싱글 랭킹 어댑터는 이미 외부 Sheets에 연결되지 않은 상태이며 이번에 새 연결하지 않았다.
- 교사 화면의 `현재 순위 발표`는 현재 상태의 스냅샷을 보여 주며 게임이나 방을 종료하지 않는다. `대결 종료`는 별도다. 최종 미제출은 순위가 없고, 동점은 공동 순위다.
- 학생의 종료 시점 기록만 학급 분석에 쓰며 보기별 인원은 보기 텍스트로 합산한다. 문제·유형·정답이 다른 변형을 임의로 합치지 않는다. 풀이 시간은 실제 기록만 평균 내며, 카트리지에 해설이 있을 때만 표시한다. 현재 내장 시험 카트리지에는 해설이 없다. 교사만 기록을 조회할 수 있다.
- 기존 신뢰 서비스에는 과거 팀 방식의 호환 경로가 남아 있으나, 새 학급 화면에서 이를 호출하거나 팀 배정을 요구하지 않는다.

## 대기실과 전광판

닉네임은 개인전에서 최대 5자다. 20명까지는 큰 명단, 21명부터는 4열의 작은 칸을 사용한다(좁은 화면은 열 수를 줄임). 1366×768에서 가상 20명과 30명 모두 명단 내부 스크롤 없이 표시했다. QR 아래 안내는 없으며 QR을 클릭하면 화면 중앙에 확대하고 다시 클릭 또는 Escape로 닫는다. 로컬 주소만 사용할 수 있는 경우의 경고는 QR 위에 표시한다. 전광판은 넓은 화면을 활용하고 20·25·30명 가상 데이터로 배치를 확인했다.

## 검증 방법과 범위

- `node --test verification/phase3d/class-data.test.mjs`: 30명 공동 순위, 실제 선택지 텍스트·평균 시간, 미제출 최종 순위.
- `verification/phase3d/integration.mjs`: 기존 단일·다중 카트리지 선택 → 개인전 → 실제 demo 에뮬레이터 교사 1·학생 3 독립 브라우저 → 중간 발표 중 게임/방 유지 → 게임 종료·실제 응답 분석 → 최종 종료, 가상 20·25·30명 전광판. 게임 종료는 시험 훅으로 유도한다.
- `verification/phase3d/layout.mjs`: 가상 20명/30명 대기실 크기와 스크롤, QR 확대·복귀. `HOJA_TEACHER_URL`은 실행 중인 시험 서버에서 제공한 교사 주소를 사용한다.
- 기존 Phase 1 원본 및 기준 해시, 정적 검사, 싱글 QR 네트워크·결정적 trace·유도 FINISH 63점, demo 에뮬레이터 인증·인가·중복 제출 검증을 유지한다.
- NOT RUN: 20~30대 실제 기기 동시 부하, 실제 학교망·물리 QR 카메라·전자칠판, 자연 완주, 운영 Firebase/GAS/Sheets. 클라이언트 보고 점수는 완전한 부정행위 방지로 검증되지 않는다. 학생 진행 중 새로고침 시 게임 상태는 복원되지 않으며 교사가 재시작을 허용한다. 서버 종료 시 시험 방 데이터는 사라진다.
