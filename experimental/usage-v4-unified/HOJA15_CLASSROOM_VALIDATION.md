# HOJA 1.5 교실 Windows Chrome 실기기 확인

이 문서는 최종 감독 승인 전 확인 목록이다. 현재 PR #14는 운영 배포 승인이 아니며, GitHub Actions의 Windows 가상 머신 결과는 실제 교실 PC 결과가 아니다. 교실 시험은 학생 데이터가 없는 격리 GAS와 시험용 통계 저장소로 진행한다.

## 기록할 환경

- 시험 일시, 후보 커밋·GAS 버전, Windows 및 Chrome 버전, 기기 모델과 화면 해상도·배율.
- 교실의 실제 화면 출력 장치, 마우스·키보드·터치 사용 여부, 교내망 접속 조건.
- 기존 교실 문제와 비교할 수 있도록 단원·문항 ID·문항 유형과 게임 모드를 기록한다. 학생 이름이나 개인 정보는 기록하지 않는다.

## 재현 및 확인

1. 5인 팀전의 첫 문제를 열고 객관식·그림·수식·OX·주관식/교사 판정을 사용한다. 오류창이 나오면 정확한 문구와 나타난 시점, 직전 조작, 확인 후 진행 여부를 기록한다.
2. 답안 입력에서 판정 표시와 토관 선택창까지 화면과 소리가 자연스럽게 진행되는지 확인한다. 판정 뒤 의도된 약 790ms 연출을 결함으로 집계하지 않는다. 멈춤이 있으면 시작·종료 시점과 해당 문항을 기록한다.
3. 싱글에서 실제 점프·풍선 충돌·마우스·키보드 답안을 확인한다. 아케이드에서 이동·점프·문항 진입과 시간 진행을 확인한다.
4. 정답과 오답, 토관 선택, 점수·아이템 변화를 확인하고 같은 문항의 오답 복습 및 게임 재시작을 수행한다. 중복 채점·점수·선택창이 생기는지 기록한다.
5. 게임 종료 후 인트로로 복귀하고 다시 게임에 진입한다. 시간 도약, 캐릭터 위치 변화, 화면 애니메이션, 배경음·효과음의 누락이나 겹침을 확인한다.
6. 별도 학생 장치에서 시험용 QR로 참여·재접속하고 교사의 게임과 같은 단원 및 문항을 확인한다. 시험용 통계에 예상한 한 건만 기록되는지도 확인한다.
7. 정상 교내망과 실제 수업에서 쓰는 네트워크 상태에서 동일한 조건을 반복한다. 새로고침 후 캐시가 있는 경우와 없는 경우를 구분한다.

## 결과 기록

각 항목에 PASS / FAIL / 미실시와 횟수, 증상·정확한 오류 문구, 후보 커밋·GAS 버전 및 증거 위치를 PR #14에 기록한다. 교실에서 재현하지 못한 오류는 원인 해결로 표시하지 않는다. 격리 테스트 이후 운영 배포 및 main 병합은 최종 감독 승인에 따른다.
